# ขั้นที่ 6: จัดลำดับฟีเจอร์

ให้คะแนน 1 ถึง 5 ตามเกณฑ์ใน research plan โดยอ้างหลักฐานจากขั้นที่ 1 ถึง 5 คะแนนเป็นการประเมินของผู้วิจัย ไม่ใช่ค่าที่วัดได้ แต่ทุกคะแนนระบุที่มาไว้แล้ว

**เกณฑ์ (5 คือดีที่สุดทุกข้อ)**
- **ผลกระทบ:** ปัญหาเจอบ่อยและเจ็บจริงแค่ไหน
- **ความต่าง:** เบราว์เซอร์และคู่แข่งยังทำได้ไม่ดีแค่ไหน
- **เบาเครื่อง:** ไม่มีภาระตอนแอปว่างได้ 5
- **ทำง่าย:** ใช้แรงพัฒนาและทดสอบน้อยได้ 5
- **ปลอดภัย:** ความเสี่ยงด้านข้อมูลส่วนตัว ความปลอดภัย และกฎหมายต่ำได้ 5

ไอเดียที่ขัดกับหลักของโปรเจกต์ถูกตัดก่อนให้คะแนน ได้แก่ ed2k, ส่วน server สำหรับ NAS และแอปมือถือ

อันดับ 1 ถึง 3 เหมือนเดิมทั้งสามแบบ จึงค่อนข้างมั่นใจได้ ส่วนวิดีโอขึ้นอยู่กับว่าให้น้ำหนักความต้องการของผู้ใช้หรือความเสี่ยงมากกว่า จึงเป็นเรื่องที่เจ้าของงานต้องตัดสินใจเอง

## ข้อเสนอ

**ทำต่อจากนี้ (เรียงตามลำดับ)**
1. **ตรวจการเชื่อมต่อกับ extension:**
   - แอปรู้เมื่อ extension ไม่ได้ติดต่อมานาน หรือเวอร์ชันไม่ตรงกัน
   - แจ้งในแอปพร้อมปุ่มพาไปแก้
   - ใช้หน้าตั้งค่าที่มีอยู่แล้ว ไม่ต้องเพิ่มหน้าต่างใหม่
2. **สแกนด้วย Microsoft Defender:**
   - สั่งสแกนไฟล์ที่โหลดเสร็จด้วย Defender ที่มีในเครื่อง
   - ถ้าพบภัยให้แสดงในแถวนั้น
   - ถ้าเครื่องใช้แอนตี้ไวรัสตัวอื่นและ Defender ถูกปิด ให้ข้ามแบบเงียบๆ
3. **บันทึกความน่าเชื่อถือในเครื่อง:**
   - บันทึกเหตุการณ์แบบหยาบตามที่เสนอในขั้นที่ 5
   - ทำหน้าสรุปสั้นๆ เช่น "โหลดต่อหลังถูกปิด 3 ครั้ง ประหยัด 2.1 GB"
4. **เลือกหลายงาน:** แรงน้อยและผู้ใช้เห็นประโยชน์ทันที

**งานเก็บกวาดที่ควรทำไปด้วย:** ลบไฟล์ตั้งค่า aria2 ที่ค้างอยู่ทุกครั้งที่เปิดแอป (ขั้นที่ 5)

**ตัดสินใจแล้ว (9 พ.ย. 2026)**
- **วิดีโอ playlist และ HLS: ไม่ทำ** เพราะต้องดูแลต่อเนื่อง และเสี่ยงเกินไปเมื่อเทียบกับเป้าหมายของโปรเจกต์
- **ลงนามรหัสและตรวจหาเวอร์ชันใหม่: ไม่ใช้งบ** โปรเจกต์มีไว้เพื่อการวิจัยและ portfolio จึงเผยแพร่เป็น open source บน GitHub แทน สร้างความน่าไว้ใจด้วยซอร์สโค้ดที่เปิดให้ตรวจได้ บันทึกการเปลี่ยนแปลง และ SHA-256 ของตัวติดตั้ง ส่วน SignPath Foundation ซึ่งลงนามรหัสให้โปรเจกต์ open source ฟรีเมื่อผ่านเกณฑ์ เก็บไว้เป็นทางเลือกในอนาคต

**ไม่ทำ:** วิดีโอ playlist และ HLS, seed ต่อหลังโหลดเสร็จ, ed2k และส่วน server สำหรับ NAS

## สิ่งที่ใช้ใน case study ได้
- กระบวนการวิจัย 5 ขั้นที่นำไปสู่การตัดสินใจ
- **การวิจัยเจอปัญหาจริงระหว่างทาง:** ไฟล์ไม่มี Mark of the Web และถูกแก้แล้วในเวอร์ชัน 1.6.3
- จุดขายเปลี่ยนจากความเร็วเป็นความน่าเชื่อถือ โดยมีผลทดสอบรองรับ
