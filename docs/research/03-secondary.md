# ขั้นที่ 3: Secondary research แทนการสัมภาษณ์

แผนเดิมของขั้นนี้คือสัมภาษณ์ผู้ใช้ 3 ถึง 5 คน แต่เปลี่ยนเป็นวิเคราะห์ข้อมูลที่ผู้ใช้เผยแพร่ไว้แล้ว ค้นเมื่อ 9 พฤศจิกายน 2026

## วิธีการ

1. **GitHub issues:** ดึง issue 40 อันดับแรกที่มี reaction มากที่สุดของคู่แข่ง open source 4 ตัว คือ Motrix, AB Download Manager, Gopeed และ XDM รวม 160 issue จากทั้งหมดประมาณ 4,600 issue แล้วจัดกลุ่มตามคำในหัวข้อ และรวม reaction ของแต่ละกลุ่ม
2. **ฟอรัมและบทความ:** ค้นกระทู้และบทความที่ผู้ใช้เล่าว่าทำไมถึงใช้หรือเลิกใช้โปรแกรมดาวน์โหลด

Reaction บน GitHub คือจำนวนคนที่กดสนับสนุน issue นั้น จึงใช้เป็นตัวแทนคร่าวๆ ได้ว่าเรื่องไหนมีคนต้องการมาก

## สิ่งที่ได้จากฟอรัมและบทความ

- **เหตุผลที่คนใช้โปรแกรมดาวน์โหลด:** เพื่อโหลดต่อได้เมื่อไฟล์ใหญ่ และตั้งเวลาโหลดช่วงเน็ตว่าง ผู้ใช้คนหนึ่งบอกว่าจะใช้กับไฟล์ที่ใหญ่กว่าประมาณ 1 GB เพราะโหลดต่อได้ ไม่ใช่เพราะเร็วกว่า
- **คนที่คิดว่าไม่จำเป็น:** มองว่าถ้าเน็ตเร็ว เบราว์เซอร์ก็พอแล้ว ข้อนี้ตรงกับผลขั้นที่ 2 ว่าจุดต่างจริงคือความน่าเชื่อถือในสถานการณ์ที่ผิดปกติ ไม่ใช่การใช้งานปกติ
- **การเปลี่ยนจาก Manifest V2 ไป V3 ทำให้ extension ดาวน์โหลดหลายตัวเลิกทำงาน:** ใน megathread ของ r/chrome มีคนหา extension มาแทน DownThemAll และมีคนแนะนำให้ใช้โปรแกรมแยกอย่าง AB Download Manager หรือ IDM แทน
- **ไม่พบแบบสำรวจหรืองานวิจัยที่เป็นระบบ** มีแต่กระทู้และบทความโปรโมต จึงไม่มีตัวเลขสัดส่วนผู้ใช้ที่เชื่อถือได้

## ข้อสรุป

1. **ความน่าไว้ใจมาก่อนฟีเจอร์** กลุ่มที่มี reaction มากที่สุดไม่ใช่ฟีเจอร์ แต่เป็นคำถามว่าโปรเจกต์ยังมีคนดูแลอยู่ไหม และไฟล์ติดตั้งปลอดภัยไหม สำหรับแอปเรา จุดที่ยังขาดคือการลงนามรหัส การอัปเดต และช่องทางแจ้งว่าใครดูแลอยู่
2. **วิดีโอยังเป็นความต้องการอันดับต้น** และแอปเรามีพื้นฐานแล้ว สิ่งที่ยังขาดคือ playlist และ HLS ซึ่ง IDM ก็ใช้เวลาเกือบทั้งปี 2026 แก้ปัญหาส่วนนี้ (ดูขั้นที่ 1)
3. **ช่องทางเชื่อมกับเบราว์เซอร์คือจุดที่พังบ่อย** extension ถูกถอดจาก store หรือเลิกทำงานเมื่อเบราว์เซอร์อัปเดต จึงควรมีการตรวจให้รู้ทันทีเมื่อการเชื่อมต่อขาด
4. **ขัดกับการออกแบบปัจจุบัน 1 ข้อ:** ผู้ใช้ torrent กลุ่มหนึ่งอยากให้ seed ต่อได้ แต่แอปเราหยุดเมื่อโหลดเสร็จ เพื่อไม่ให้อัปโหลดโดยผู้ใช้ไม่รู้ตัว ถ้าจะเพิ่ม ควรเป็นตัวเลือกที่ปิดไว้ตั้งต้น
5. **เรื่องเล็กที่ทำได้เร็ว:** เลือกหลายงานเพื่อลบหรือหยุดพร้อมกัน และเลือกไฟล์ใน torrent

## ข้อจำกัด

- **เป็นเสียงของผู้ใช้กลุ่มเดียว:** คนที่เปิด issue บน GitHub มักเป็นผู้ใช้ระดับสูงและนักพัฒนา และมีผู้ใช้จีนจำนวนมากใน Motrix กับ Gopeed จึงไม่ได้แทนผู้ใช้ทั่วไปหรือผู้ใช้ไทย
- **ข้อมูลเอียงไปทางเรื่องเก่า:** issue เก่ามีเวลาสะสม reaction นานกว่า
- **จัดกลุ่มด้วยคำค้น:** อาจจัดผิดบางข้อ และมีประมาณ 42 issue ที่ไม่เข้ากลุ่มไหน
- **ไม่ได้อ่านเนื้อหาทุก issue:** อ่านแค่หัวข้อ จึงอาจพลาดบริบท
- **ไม่แทนการสัมภาษณ์:** ยังตอบไม่ได้ว่าผู้ใช้ทั่วไปเจอปัญหาอะไรบ่อยที่สุดในชีวิตจริง
