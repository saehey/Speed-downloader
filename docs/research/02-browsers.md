# ขั้นที่ 2: เทียบกับเบราว์เซอร์

ทดสอบเมื่อ 9 พฤศจิกายน 2026 ด้วย Chrome 156.0.8078.81 และ Edge 157.0.4341.42 บนเครื่องที่ใช้พัฒนา เบราว์เซอร์ใช้โปรไฟล์ชั่วคราวและโหลดจาก server ในเครื่อง ทุก request ถูกบันทึกไว้ ไฟล์ทดสอบขนาด 48 MB และจำกัดความเร็วรวมที่ 4 MB/s เท่ากันทั้งเบราว์เซอร์และแอปเรา

Script อยู่ใน [scripts](scripts) และรันซ้ำได้

## ปีนี้เบราว์เซอร์เพิ่มอะไรด้านดาวน์โหลด

ไม่พบฟีเจอร์ดาวน์โหลดใหม่ที่สำคัญในปี 2026 Chrome ยังใช้แถบดาวน์โหลดแบบ bubble ที่เปิดตัวในปี 2023 ส่วน Edge ใช้อัปเดตใหญ่ในเดือนพฤษภาคมกับ Copilot แทบทั้งหมด ข้อสรุปนี้มาจากการค้นเว็บเท่านั้น ยังไม่ได้อ่าน release notes ของทุกรุ่น

## ผลทดสอบ

| สถานการณ์ | Chrome 156 | แอปเรา 1.6.3 |
|---|---|---|
| **เบราว์เซอร์หรือแอปถูกบังคับปิดกลางทาง** เช่น ค้าง ไฟดับ หรือ Windows รีสตาร์ตเพื่ออัปเดต | ขึ้นว่า "Failed - Crash" และมีปุ่ม Resume แต่พอกดแล้ว**เริ่มโหลดใหม่ตั้งแต่ไบต์แรก** โดยไม่ส่ง `Range` ส่วนที่โหลดไปแล้ว 14 MB จึงเสียเปล่า | เปิดแอปใหม่แล้วโหลดต่อเอง server ส่งข้อมูลรวม 48 และ 49 MB ใน 2 รอบ จากไฟล์ 48 MB จึงโหลดซ้ำไม่เกินประมาณ 1 MB |
| **ลิงก์หมดอายุระหว่างหยุดไว้** | ขึ้นว่า "Failed - Forbidden" ไม่มีปุ่ม Resume มีแต่การเริ่มใหม่ และใส่ลิงก์ใหม่แทนไม่ได้ | อธิบายว่าลิงก์อาจหมดอายุ และให้ใส่ลิงก์ใหม่โดยเก็บส่วนที่โหลดแล้วไว้ (เทสต์ `an expired link can be replaced and keeps its progress`) |
| **ไฟล์บน server เปลี่ยนระหว่างหยุดไว้** | ปลอดภัย ส่ง `If-Range` พร้อม ETag เมื่อไม่ตรงจึงได้ไฟล์ใหม่ทั้งไฟล์ ไม่มีไฟล์เสีย | ปลอดภัยเหมือนกัน ตรวจ ETag เองแล้วบอกว่าต้องเริ่มใหม่ (เทสต์ `never resumes onto a file that changed on the server`) |
| **หยุดชั่วคราวแล้วโหลดต่อ** | ไม่ปิด connection ระหว่างหยุด แค่หยุดอ่าน ถ้า server ตัดการเชื่อมต่อก็โหลดต่อด้วย `Range` ได้ถูกต้อง | โหลดต่อได้ถูกต้อง |
| **จำนวน connection ต่อไฟล์** | 1 | สูงสุด 16 |
| **Mark of the Web** | มี | มีตั้งแต่ 1.6.3 |
| **ตรวจมัลแวร์** | มีข้อความ "Scanning for malware…" ระหว่างโหลด (Safe Browsing) | ไม่มี มีแค่ Mark of the Web ให้ SmartScreen ตรวจตอนเปิดไฟล์ |

### Edge
Edge ใช้ส่วนดาวน์โหลดจาก Chromium เหมือน Chrome แต่หน้า `edge://downloads` สร้างต่างกัน script จึงกดหยุดและโหลดต่อใน Edge ไม่ได้ สิ่งที่วัดได้จาก Edge คือ:
- ใช้ 1 connection เหมือน Chrome
- ใส่ Mark of the Web
- เมื่อ server ตัดการเชื่อมต่อ จะโหลดต่อเองโดยส่ง `Range` และ `If-Range`

ส่วนกรณีบังคับปิด ลิงก์หมดอายุ และไฟล์เปลี่ยน ยังสรุปผลของ Edge ไม่ได้

## ความสามารถที่เบราว์เซอร์ไม่มี
ส่วนนี้ไม่ได้ทดสอบ ดูจากหน้าการตั้งค่าดาวน์โหลดของเบราว์เซอร์ ซึ่งมีแค่โฟลเดอร์ปลายทางและการถามก่อนบันทึก:
- คิวและจำนวนไฟล์ที่โหลดพร้อมกัน
- ตั้งเวลาโหลด
- จำกัดความเร็ว
- แยกโฟลเดอร์ตามชนิดไฟล์
- BitTorrent
- ปิดเครื่องเมื่อโหลดเสร็จ

## สรุป: แอปเราดีกว่าเบราว์เซอร์ตรงไหน

1. **ไม่เสียส่วนที่โหลดไปแล้วเมื่อเกิดเหตุไม่คาดคิด** เช่น ค้าง ไฟดับ หรือรีสตาร์ต เป็นจุดต่างที่ใหญ่ที่สุดจากการทดสอบ
2. **ลิงก์หมดอายุแล้วยังโหลดต่อได้** ถ้าหาลิงก์ใหม่ของไฟล์เดิมมาใส่
3. **โหลดหลาย connection** ช่วยได้กับ server ที่จำกัดความเร็วต่อ connection แต่จากการวัดก่อนหน้า ไม่ได้เร็วขึ้นทุก server
4. **จัดการงานจำนวนมากได้** ด้วยคิว ตั้งเวลา จำกัดความเร็ว และแยกโฟลเดอร์

**ข้อที่เบราว์เซอร์ทำได้ดีกว่าเรา:** การตรวจมัลแวร์ระหว่างโหลด ส่วนการป้องกันไฟล์เสียเมื่อไฟล์บน server เปลี่ยน ทั้งสองฝั่งทำได้เท่ากัน

## ผลต่อการเลือกฟีเจอร์

- **ความน่าเชื่อถือเป็นจุดขายที่พิสูจน์ได้จริง** ข้อ 1 และ 2 ควรเป็นเรื่องหลักใน case study และในหน้าแนะนำแอป ไม่ควรเน้นเรื่องความเร็ว
- **ช่องว่างด้านความปลอดภัยที่ควรพิจารณาต่อ:** สแกนไฟล์ด้วย Microsoft Defender ที่มีในเครื่องหลังโหลดเสร็จ เพื่อปิดจุดที่เบราว์เซอร์ทำได้แต่เรายังไม่มี
- **ไม่ควรลงแรงกับการป้องกันไฟล์เปลี่ยน** เพราะทำได้เท่ากันอยู่แล้ว

## ข้อจำกัด

- รันแต่ละกรณีกับ Chrome เพียง 1 รอบ ส่วนการบังคับปิดแอปเรารัน 2 รอบ
- ใช้ server ในเครื่องที่ไม่มีความหน่วงจริง จึงยังไม่รู้ผลกับ server จริงบนอินเทอร์เน็ต
- การบังคับปิดใช้ `taskkill /F` และ `Stop-Process -Force` ซึ่งใกล้กับการค้างหรือไฟดับ แต่ไม่ใช่การปิดแบบปกติ ยังไม่ได้ทดสอบว่า Chrome ทำอย่างไรเมื่อผู้ใช้ปิดหน้าต่างเองตามปกติ
- ยังไม่ได้ทดสอบ Firefox
